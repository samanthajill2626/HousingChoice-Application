M11 is a real bug, not an equivalent mutant:
- The dashboard renders under `StrictMode` (`dashboard/src/main.tsx:15`).
  StrictMode's first mount starts the locked read and aborts it at once.
- Since main `b222a4ac` (merged here at S7), the client rejects a signalled
  request aborted in the same tick (`client.ts` on main, `:117-129`).
- Without the guard, that dropped read flips the section to "Couldn't
  load ..." with Try again, and enables Create. A Create in that window
  posts no snapshot and no prefill, while the live read is still in flight.
  This happens in dev and in every e2e run.
- The new case:
  - wraps the form in `StrictMode`;
  - mocks `getContact` with the client's semantics (one microtask, then
    reject with `signal.reason` when aborted);
  - holds the live read, and asserts no failure line, the loading line and
    a disabled Create;
  - then lands the read, and asserts the note, an enabled Create and a body
    carrying `ROSA_SNAPSHOT`.

### Edit property form - `ListingEditForm` (`dashboard/src/routes/listing/ListingEditForm.tsx`)

- Props unchanged: `{ unit, onClose, onSaved }`. Host: ListingDetail's
  "Edit property" menu item.
- Dialog `Edit property` (the Modal `<h2>` names it). The header has a
  `Close` button. Footer: `Cancel` and `Save`. While saving, `Save` reads
  `Saving...` and both are disabled. The form id is `listing-edit-form`.
- Legend at the top (a `<ul>`): `On flyer - tenants see it on the public
  flyer.` and `Staff only - never leaves the dashboard.` The old "...are
  shown on the public flyer." hint is gone.
- Fields in D10 order, by accessible name (the tag is in each control's
  DESCRIPTION, never its name):
  1. `Housing authorities`:
     - a combobox; chips have `Remove <name>` buttons;
     - description: its own hint / note / error, then `On flyer` LAST.
  2. `Beds` (spinbutton, step 1) and `Baths` (step 0.5): On flyer.
  3. `Voucher sizes accepted`:
     - a GROUP of toggle buttons with `aria-pressed`: `Studio`, `1`-`4`, and

     - description: `On flyer`, `Accepts: <Studio | n BR, ...>` (or
       `Accepts: none recorded`), then, for stored values with no chip,

  4. `Rent min`, `Rent max` (On flyer) and `Payment standard` (Staff only):
     spinbuttons, step 1.
  5. Address:
     - a visible `Address` label plus an `On flyer` tag;

     - textboxes, On flyer;

  10. `Same-day RTA`: a checkbox, On flyer.
  11. Heading `Requirements` (`<h3>`), then RequirementsFields:
      - groups `Screening`, `Pets`, `Move-in costs`, `Touring`, and nested

### New property form - `UnitCreateForm` (`dashboard/src/routes/listing/UnitCreateForm.tsx`)

- Props unchanged: `{ landlordId?, onClose, onCreated }`. Hosts:
  ContactDetail "+ Add a property" (LOCKED) and ListingsList "+ New
  property" (picker).
- Dialog `New property`, with a header `Close` button. Footer:
  - `Cancel`: disabled while creating.
  - `Create`: reads `Creating...` while creating. Disabled until a landlord
    is known, while creating, and while the LOCKED landlord's record loads.
    Playwright's click waits for it.
- The form id is `unit-create-form`. The legend is the same as the Edit
  form's.
- `Owning landlord` comes first: a visible label span plus a `Staff only`
  tag beside it.
  - Locked: a read-only box showing the landlord's name, or the raw id
    until a read lands. It has no role.
  - Picker: a combobox `Owning landlord` (aria-label), described by
    `Staff only`. Options are named by display name; a picked landlord
    shows a `Clear Owning landlord` button.
- Then the same fields as the Edit form, in the same order, with the same
  names, tags and notes. Nothing is stored, so there is no off-chip line.
- The Requirements section, under the `Requirements` heading:
  - Locked, while loading: `Loading <L>'s requirements...` (role status).
    The fields are not rendered.
  - Locked, after a failed read: `Couldn't load <L>'s requirements, so this
    property starts without them. You can apply them from the landlord page
    later.` (role status), then a `Try again` button. The fields show,
    blank. Create is allowed.
  - Filled, when the landlord holds at least one requirement: `Filled in
    from <L>'s requirements. Change anything that is different for this
    property.` (a muted paragraph, no role).
  - `<L>` is the landlord's display name: first + last name, else the
    phone, else `Unknown contact`. Until a read names the locked landlord
    it is `the landlord`.
  - Picker path: the section is editable before a pick. The first pick
    fills it; a DIFFERENT pick refills it, replacing what was typed.
    Re-picking the same landlord keeps what was typed.
- Errors (`role="alert"`):
  - landlord refusals: `Only a landlord can be a property's landlord of
    record.` and `That landlord no longer exists.`;
  - anything else: `Couldn't create the property - please try again.`;
  - a bad number: `<Label> must be a number 0 or greater.`;
  - a 422 shows under the picker.
  - There is no special 400 `deposit_conflict` copy: the form cannot
    produce one, since One month's rent never sends an amount.
- What it SENDS: `createUnit(body)`, typed `CreateUnitBody`
  (`endpoints.ts:976`, the only change in that file plus its import at
  `:28`). The body carries:
  - `landlordId`;
  - trimmed non-empty `subzone`, `utilities`, `accessibility`,
    `lease_terms`, `listing_link`, `video_url`, `application_process`,
    `notes`;
  - `washer_dryer`, when recorded;
  - `same_day_rta: true`, when ticked;
  - the non-blank numbers;
  - `voucher_size_accepted`: the list (ascending), when non-empty;
  - requirement fields, NON-BLANK only: `true` boxes, trimmed text, numbers
    with 0 included; never `deposit` while One month's rent is ticked;
  - `accepted_authorities`, when non-empty;
  - `address`, when any part is filled;
  - `requirements_snapshot` = `{ landlordId, <8 items: every unit key,
    null for blank> }`, sent ONLY when the landlord's record was read
    (locked: after `getContact` landed; picker: from the list entry). It is
    never sent after a failed read.
