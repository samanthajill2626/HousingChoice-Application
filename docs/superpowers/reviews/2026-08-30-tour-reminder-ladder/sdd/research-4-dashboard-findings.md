## GAPS — things the relabel or the new skip reason would break that the plan omits

**G1 — Nothing guards the app→dashboard direction of the union.** The `Record` type only catches *union member added, label missing*. If a future app-side reason is added and the dashboard union is never touched, the chip silently reads `Skipped` (§2a) and no test anywhere notices: `REMINDER_SKIP_REASON_LABELS` has **no importer in any test file** (verified by grep), and `dashboard/src/api/types.test.ts` only exercises `suggestionResolutionErrorMessage` + one `sendNowErrorMessage` line (`:79`). The plan's own Task 3 rationale says "let the label test be what catches a future divergence" — but a single `booked_too_late` label test catches only *that* token. A cheap fix the plan does not propose: a coverage test in `types.test.ts` modelled on the existing `SERVER_CODES` pattern (`types.test.ts:9-24, 29-35`) that enumerates the nine+one reasons literally and asserts each has a non-generic label — that is exactly the shape the file already uses for suggestions, including the comment "Listed here rather than imported from the map so that DELETING an entry from the map is a test failure".

**G2 — The skip chip has no `?? rawReason` fallback, unlike every sibling.** `RemindersPanel.tsx:103` is the only label lookup in this family without one; compare `:318` and `ScheduledCard.tsx:85` (whose comment `:80-84` records a production incident that motivated the fallback). Degrading to `'Skipped'` is safer than `undefined`, but it means a version-skewed bundle can never show the operator *anything* about why. Not in scope, but the plan asserts the degrade is acceptable without noting the panel is deliberately inconsistent here.

**G3 — `RemindersPanel.tsx:189` renders `err.message` RAW for the LIST fetch.** `error: err instanceof ApiError ? err.message : 'Failed to load reminders',`. This is the exact hazard the plan calls out for `TourDetail.tsx:345` and cites `RemindersPanel.tsx:278-279` as the precedent against — yet the same file violates it 90 lines above. The existing test (`RemindersPanel.test.tsx:264-268`) uses `new ApiError(500, 'boom', 'boom')` and only asserts `role="alert"` exists, so a snake_case code would sail through. Load-shaped, not send-shaped, so the send map is wrong for it — but the plan's "never a machine code in front of staff" rule is stated as universal and this site is untouched.

**G4 — The "the" insertion desynchronises the reminder and nudge aria conventions.** After Task 8: reminders read `Send the Day before reminder now` / `Cancel the Day before reminder`; nudges keep `Send Receipt check nudge now` / `Cancel Receipt check nudge` (`DeadlinesNudgesCard.tsx:273`, `:284`), pinned at `e2e/support/selectors.md:73` and `e2e/tests/dashboard-next/placements-page.spec.ts:216-226`, `DeadlinesNudgesCard.test.tsx:287,308,309,319`. The plan says "uniformly for every kind" — meaning every *reminder* kind — but never states that nudges are deliberately left alone. Given the two panels are explicit mirrors of each other (the "A10 distinct accessible name" comments are near-verbatim: `RemindersPanel.tsx:339-341` vs `DeadlinesNudgesCard.tsx:265-267`), this needs an explicit decision recorded, or a reviewer will read it as a missed sweep. Precedent that "the" is house-acceptable: `e2e/support/selectors.md:93` already pins `Send the relay group now`.

**G5 — `e2e/scenarios/steps.ts:3368-3376` filters reminder rows by label text.** `const label = REMINDER_KIND_LABELS[kind];` with a `hasText` filter (docblock `:3368`: "Rows are scoped by the rung's staff label (REMINDER_KIND_LABELS)"). After the mirror flips to `'4 hours before'`, every `expectReminderRung('morning_of', …)` call (`e2e/tests/scenarios/scheduled-visibility.spec.ts:108`) filters on the substring `4 hours before`. Playwright `hasText` is a substring match over the whole `listitem`, which also contains the composed **body** and the chip. Nobody has verified that no rung body contains the phrase "4 hours" — a `hasText: 'Morning of'` collision was impossible; `'4 hours before'` is prose-shaped and could collide with future copy. The plan says only "it is a verbatim mirror - say so is why"; it does not flag the changed collision profile of the row selector.

**G6 — `docs/issues/tour-reminders-panel-e2e-flake.md:112` quotes the label verbatim** (`    "App: Reminders panel shows 'Morning of' as upcoming"   (spec line 98)`). Task 10 (`plan:3122-3126`) does address it, so it is covered — but it is *not* in Task 8's file list, and Task 8 is where the relabel lands. If Tasks 8 and 10 land in different commits, the tree carries a stale quote in between, and Task 8's `git add` list (`plan:2826`) does not include it.

**G7 — The blank-preview note interacts with the new skip reason in a way only one plan sentence covers.** `booked_too_late` makes **visible skipped rows common** (the plan says so at `2178-2181`), and the body `<p>` at `RemindersPanel.tsx:365` renders for *every* state with no gate. A `booked_too_late` row whose body composed fine will show real copy under a "Skipped - booked too late for this reminder" chip — arguably confusing (a preview of a message that will never send), but that is pre-existing behaviour for `past_event` too. The plan's state-agnostic empty-branch decision is right; what it omits is that the *non-empty* case now becomes far more common and nobody has decided whether a skipped rung should show its body at all.

**G8 — `css: false` in `dashboard/vite.config.ts` means the muted-note styling is untestable.** Any Task 5 test for the blank-preview note can only assert the sentence text; it cannot prove the note landed in `.muted` / `.suppressionMuted` / `.scheduledSkipMuted` rather than inline styles or the default `.body`. The plan says "never inline styles" (`2189`) but provides no verification path for that instruction. Worth stating explicitly so a reviewer does not expect a class assertion.

**G9 — `TourDetail.test.tsx` has four other `err.message`-raw sites that the narrow 409/404 pins do not cover.** `TourDetail.tsx:305, 366, 411, 426`. Plan case 12 exists specifically to "pin the narrow routing so a later 'simplification' cannot widen the send map over a load failure" — but the four neighbouring catches all still render raw codes, so the file's *pattern* still teaches the wrong thing to the next contributor. Not a break, but the plan's justification for case 12 is undermined by the surroundings it leaves in place.

**G10 — `TimelineScheduled` is a THIRD hand-duplicated reminder-kind union** (`types.ts:2391`: `reminderKind?: 'confirmation' | 'day_before' | 'morning_of' | 'en_route' | 'no_show_checkin';` — an inline literal union, not `ReminderKind`). It carries no `skipReason`, so `booked_too_late` never reaches it, and it carries no label render, so the relabel never reaches it either. Both true today — but the plan's "the two unions are hand-duplicated" framing (Task 3) undercounts the kind duplication at three (`app/src/repos/tourRemindersRepo.ts:30-34`, `dashboard/src/api/types.ts:1177-1182`, `dashboard/src/api/types.ts:2391`) plus the e2e mirror at `e2e/scenarios/steps.ts:128`. Nothing breaks now; it is the next divergence waiting to happen.
