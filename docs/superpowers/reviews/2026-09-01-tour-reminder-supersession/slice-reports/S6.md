## 4. T6.4: the fixture repair, and the consequence it had

`relayApi.test.ts`'s `seedTourGroup` (`:1440`) arms through the REAL armer
against a tour it builds by hand. Post-S2 those rows are STAMPED on a
POINTERLESS tour - the interrupted-pointer-write cell - so every rung in the
bucket would have read `superseded`. It now patches `currentLadderId` from the
arm's return, exactly as `routes/tours.ts` does post-S3, and RETURNS the
`ladderId`.

**The unpredicted consequence.** Repairing the helper broke the EXISTING
discontinued case (`:1528`) in the opposite direction: it writes a pause-era
`confirmation` row BY HAND with no `ladderId`, which on a now-pointed tour is
itself the interrupted-pointer-write cell - so it read `superseded` and the case
proved the wrong annotation. Caught by the first green run
(`AssertionError: expected { reason: 'superseded' } to deeply equal { reason: 'discontinued' }`).

Fixed by stamping that hand-written row with the helper's returned `ladderId`,
which is why the helper returns it. The case's subject is the KIND, so pinning
it to the live ladder is what it meant all along; the coverage is unchanged.
**Generalisable rule for S7-S9: once a helper points its tour, every row a case
adds BY HAND to that tour must be stamped or it is superseded.**

`tourRemindersApi.test.ts`'s `seedReminder` gained an optional `ladderId` for the
same reason - omitted by default, which paired with its pointerless
`seedQuietTour` is the pre-migration exemption every legacy case in that file
already relies on.
