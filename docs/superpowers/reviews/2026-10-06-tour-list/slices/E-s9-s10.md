## Divergences from the plan, the worklists or the rulings, and why

1. Type placement follows ruling D-2 (after the `ToursPage` interface), not
   plan S9.1's "after undatedTourLabel" - the ruling decides it.
2. P15's RED signal. With D-5's href (`/tours/all?when=past`) an UNprevented
   click navigates to the very same URL, so the plan's RED ("the probe still
   reads /tours/all?when=past") would be green without P15. The probe also
   exposes the history entry key, and the test asserts it is unchanged (any
   navigation, even a same-URL REPLACE, makes a new key and drops the entry's
   state - which is what P15 protects). Observed RED above.
3. The P15 test is async: after the modified clicks it waits for exactly
   four jsdom "Not implemented: navigation" reports while its console.error
   spy is installed, then asserts each is that message. jsdom queues the
   anchor navigation in a task, so with a synchronous test the reports landed
   in the NEXT test's stderr after afterEach restored the spy (seen once).
   The wait also proves each modified click reached the browser default
   (jsdom runs activation only for an unprevented click). Beside the plan's
   ctrlKey it also clicks with metaKey, shiftKey and button 1 (all `true`, no
   router move).
4. The P15 handler is a named module function attached with the file's own
   spread idiom, instead of the plan's inline lambda - the same predicate.
5. routes.test.ts follows E-2 (keep :381 verbatim, add a comment line), not
   plan 10.1's "extend the comment at :381".
6. Extra assertions / cases beyond the plan (cases 3 and the bare-links
   PIN), listed above. No plan case was dropped.
7. Header comment (ToursPage.tsx): lines 1-3 (ASCII) reworded from "three
