## Deviations and judgment calls (all within the spec)

1. **The GLOSSARY bullet does not restate the take-down caveat.** WL-33
   lists "Setup not a take-down" as bullet content. The dispatch says to
   state the caveat ONCE, in STATUS-MODEL section 6. The bullet therefore
   only points there: "Whether and how a flyer comes down:
   [STATUS-MODEL.md] section 6".
2. **STATUS-MODEL folds the spec's third item into the Setup bullet.** The
   spec's "every status but Setup serves the public flyer" is the Setup
   bullet's parenthetical (with `FLYER_PUBLIC`), not a separate bullet. The
   caveat bullet sits after the Available bullet. It says "the property's
   next placement event", which is more exact than R3-12's "the next
   placement event".
3. **selectors.md:144 names the fallback row instead of "next row".** R3-10
   wrote "(next row)" for a row placed after :143. WL-33 moved that row to
   :50, so :144 says "(the `Public flyer fallback` row)".
4. **The fallback row adds two facts that R3-10's cell lacks.** Both come
   from the spec:
   - assert the absence only after the h1 is visible (G3);
   - the form sends the route unitId only when, trimmed, it is 1 to 200
     characters (D4). This is what makes WL-38's `needs_review` expectation
     hold.

   "Loading..." is written as "a loading line": the live glyph is U+2026.
5. **abuse-hardening (c) qualifies "leaves Follow up".** It now reads "for
   an Available property, leaves Follow up (Follow up lists Available
   properties only)". Applied to every public unit, the old text would have
   claimed that old links churn Follow up, which R4-3 forbids.
6. **abuse-hardening point 3 avoids "every id".** R3-11's "every id in an
   old Matching or broadcast text qualifies" is not exact: a deleted or
   Setup id does not qualify. It now reads "so the ids in old Matching and
   broadcast texts count too". The Problem sentence keeps the spec's own
   phrasing, scoped to "every unitId whose property is public".
7. **Spelling on touched lines.**
   - StatusBadge.tsx:46 now says "color", which follows Cameron's
     American-spelling rule for written text. Lines 6 and 22 of that file
     still say "colour"; they were not touched.
   - In Timeline.test.tsx I inserted a line (:444) instead of rewrapping.
     That keeps the "colour" line (:446) byte-unchanged.
8. **units.ts:982-983 are 85 and 88 characters long.** Rewrapping would have
   touched the non-ASCII :984. There is no max-len rule.
