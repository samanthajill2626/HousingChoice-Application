### 1a. The all-kinds-silently-skipped return is UNREACHABLE (T2.1 case c)

The prompt asked to cover the `dueAt < now` silent skip "if reachable". It is
not, and the argument is short enough to pin here because S3/S4 will lean on it:

`day_before` ALWAYS writes a row on a tour that has a `scheduledAt`. Its four
exits are booked-too-late (row), silent past-dueAt, past_event (row) and
superseded/stale (row) or the live create (row). The silent skip is unreachable
for that kind because it sits BELOW the booked-too-late branch: if
`bookedTooLate` is false then `now <= rawAt - 4h`, so `rawAt > now`, and
`clampOutOfQuietHours` only ever moves an instant FORWARD (`quietHours.ts:153-163`
returns the window END at or after the input), so the stored `dueAt >= rawAt > now`.

So `rows.length === 0` has exactly one producer: `typeof scheduledAt !== 'string'`.
The `created.length === 0` guard on the return is still written as a general
guard (and commented as such) rather than folded into the early return, because
it is the CONTRACT S3 relies on - "never point a tour at a ladder with no rows" -
not an assertion about today's reachable paths.

Consequence worth naming for S3: on a tour with a `scheduledAt`, `ladderId` is
never `null`. The `null` branch in `tours.ts` is the time-less-tour branch, which
the route already gates on.
