# AI Run Log Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every conversation-fact-extraction run a durable, queryable record - the input window, the model's raw response, every finding and what we did with it, and the human verdict that followed - readable through an admin-only two-pane log at `/settings/ai-runs`.

**Architecture:** A new single-key `ai_runs` DynamoDB table holds two disjoint row kinds (`run#<runId>` full records, `ptr#<entityKey>#<startedAt>#<runId>` adjacency pointers) behind one sparse `byEntity` GSI, all TTL'd at 90 days. `processRow` in `app/src/jobs/extraction.ts` stops throwing and instead builds a `RunDraft` as it goes, returning `{ outcome, draft }` on every terminal path; `runDueExtractions` performs the single best-effort write. Verdicts are stamped later by three resolution surfaces via targeted nested-path `UpdateItem`s guarded with `attribute_exists(itemId)`.

**Tech Stack:** TypeScript (NodeNext ESM), Express, DynamoDB via `@aws-sdk/lib-dynamodb`, Vitest, React 19 + react-router-dom, Playwright, Terraform.

**Authoritative spec (frozen, do NOT redesign):** `docs/superpowers/specs/2026-08-06-ai-run-log-design.md`. Section references below (`spec 6.1`, `spec 7.2`, ...) point at it. If you believe the spec is wrong, STOP and raise it - do not deviate silently.

```ts
// Shared vocabulary for the AI run log (design 2026-08-06, sections 6-7).
//
// LEAF MODULE BY DESIGN: this file imports NOTHING. apply.ts describes its
// per-target outcomes with these types, and the ai_runs repo stores them - but
// apply.ts never imports the repo, so the apply layer gains no ai_runs
// dependency (design section 7.3/8: that separation is exactly why the
// `superseded` stamp is routed through the JOB rather than through apply).

/** The twelve targets a run can decide about. Order is the display order. */
export const DECISION_TARGETS = [
  'firstName',
  'lastName',
  'voucherSize',
  'housingAuthority',
  'pets',
  'evictions',
  'tenure',
  'porting',
  'address',
  'status',
  'type',
  'phone',
] as const;

export type DecisionTarget = (typeof DECISION_TARGETS)[number];

/** True when `value` is one of the twelve targets (route/param validation). */
export function isDecisionTarget(value: unknown): value is DecisionTarget {
  return typeof value === 'string' && (DECISION_TARGETS as readonly string[]).includes(value);
}

/**
 * What the MODEL said for a target, read from rawText BEFORE any folding or
 * downgrading (design 7.1). `none` is an explicit decline; `absent` means the
 * target never appeared in the response at all. Conflating them would
 * manufacture evidence of evaluation that never happened.
 */
export type ProposedOp = 'write' | 'suggest' | 'none' | 'absent';

/** What WE did with the target. */
export type DecisionOutcome = 'wrote' | 'suggested' | 'dropped' | 'no_finding' | 'not_addressed';

/**
 * Every discard branch in services/extraction/apply.ts, re-enumerated against
 * the code (design 7.2). Deliberately EXCLUDED: `note_line_filtered`
 * (apply.ts:409-411 - note lines are not decision targets, so it would be an
 * orphan key) and `address_no_usable_parts` (apply.ts:226 - unreachable,
 * schema.ts:258-263 already drops a zero-part address before apply runs).
 * `lossy_address` and `demoted_inferred_role` are NOT drop reasons either -
 * both produce SUGGESTIONS (apply.ts:256-284 and :189-211) and are recorded as
 * outcome 'suggested' with demotedFrom 'write'.
 */
export const DROP_REASONS = [
  'wrong_contact_type', // apply.ts:169, :224
  'invalid_value', // apply.ts:175
  'equal_to_current', // apply.ts:198, :270
  'status_not_onboarding_tenant', // apply.ts:338
  'type_already_classified', // apply.ts:360
  'phone_not_canonicalizable', // apply.ts:367
  'phone_already_owned', // apply.ts:369
  'phone_owned_by_other', // apply.ts:379
  'dismissed_before', // apply.ts putSuggestionSafe
  'repo_error', // apply.ts putSuggestionSafe
] as const;

export type DropReason = (typeof DROP_REASONS)[number];

/**
 * TOTAL - never blank, because blank is indistinguishable from "nobody has
 * looked yet" (design 7.3).
 *   wrote                  -> auto_applied
 *   suggested              -> pending -> accepted | dismissed | superseded |
 *                             superseded_by_human_edit
 *   dropped                -> not_presented
 *   no_finding/not_addressed -> not_presented
 */
export type Verdict =
  | 'auto_applied'
  | 'pending'
  | 'accepted'
  | 'dismissed'
  | 'superseded'
  | 'superseded_by_human_edit'
  | 'not_presented';

/** One target's full story: what the model proposed, what we did, what a human decided. */
export interface RunDecision {
  proposedOp: ProposedOp;
  /** The RAW value from rawText (pre-coercion). PII by design (design 6.2). */
  proposedValue?: string;
  /** The apply-layer coerced value actually written/suggested. PII by design. */
  coercedValue?: unknown;
  /** What the field held BEFORE. The single field that makes "changed from
   *  what?" answerable - deliberately kept (design 6.2). PII by design. */
  previousValue?: string;
  reason?: string;
  /** Set to 'write' when a write was ROUTED to the suggest path (Layer-3
   *  inferred-role demotion, or a lossy address write). Not a drop. */
  demotedFrom?: 'write';
  outcome: DecisionOutcome;
  dropReason?: DropReason;
  verdict: Verdict;
  verdictAt?: string;
  verdictBy?: string;
}

/** One message that actually reached the model. Ids only - never text (design 6.1). */
export interface RunWindowMessage {
  tsMsgId: string;
  /** MessageItem.type at run time (sms | mms | call | email). */
  type: string;
  /** MessageItem.direction at run time (inbound | outbound). */
  direction: string;
  /** 'new' = newer than the cursor (full-fidelity read); 'seen' = context. */
  tier: 'new' | 'seen';
  /** The EXACT per-message cap this run applied - not just the tier label, so a
```

```ts
// AI run log repo - the ai_runs table (design 2026-08-06, section 5).
//
// ONE single-key table holds two kinds of item, disjoint by itemId prefix:
//
//   run#<runId>                          the full run record
//   ptr#<entityKey>#<startedAt>#<runId>  an adjacency-list pointer
//
// Only ptr# rows carry entityKey/sortKey, so the byEntity GSI is TRULY sparse
// and holds pointers ONLY. Reading a scope is Query(byEntity) newest-first then
// ONE BatchGetItem for that page's run# rows. No Scan, ever.
//
// Two BatchGetItem mechanics the reader honors, because getting either wrong is
// silent (design 5.3):
//   - responses are UNORDERED; we re-sort by the pointer sortKey we already
//     hold and NEVER trust response order;
//   - UnprocessedKeys can come back under throttling; we retry with backoff
//     before rendering a partial page.
//
// TTL: 90 days, same expires_at on both row kinds. DynamoDB TTL is asynchronous
// and may lag up to 48h, unordered - so a pointer whose run# row is already
// reaped renders as EXPIRED rather than erroring.
//
// PII: rawText, rawResult, and decision values ARE contact PII by design
// (design 6.2) - that is the point of the feature. They live in DynamoDB only,

export function createAiRunsRepo(deps: RepoDeps = {}): AiRunsRepo {
  const doc = deps.doc ?? getDocumentClient();

  const log = deps.logger ?? defaultLogger;

  return {
    async putRun(input) {
      const expires_at = runExpiresAt(input.startedAt);
      const record: AiRunRecord = { ...input, itemId: runItemId(input.runId), expires_at };
      await doc.send(new PutCommand({ TableName: table, Item: record }));
      for (const entityKey of pointerEntityKeys(input)) {
        const pointer: AiRunPointer = {
          itemId: pointerItemId(entityKey, input.startedAt, input.runId),
          entityKey,
          sortKey: runSortKey(input.startedAt, input.runId),
          runId: input.runId,
          expires_at,
        };
        await doc.send(new PutCommand({ TableName: table, Item: pointer }));
      }
      // Ids + counts only. NEVER the record (it carries PII by design).
      log.debug(
        { runId: input.runId, conversationId: input.conversationId, outcome: input.outcome },
        'ai run recorded',
      );
      return record;
    },

    async getRun(runId) {
      const { Item } = await doc.send(

      return Item as AiRunRecord | undefined;

      throw new Error('not implemented');
    },
```

```ts
  /**
   * One BatchGetItem for a page of run# rows, retrying UnprocessedKeys with
   * backoff before we render a partial page (design 5.3). A key that is still
   * unprocessed after MAX_BATCH_ATTEMPTS is simply absent from the map, and the
   * caller renders it as expired - a degraded row beats a failed page.
   */
  async function batchGetRuns(runIds: string[]): Promise<Map<string, AiRunRecord>> {
    const found = new Map<string, AiRunRecord>();
    let keys = runIds.map((runId) => ({ itemId: runItemId(runId) }));
    for (let attempt = 0; attempt < MAX_BATCH_ATTEMPTS && keys.length > 0; attempt += 1) {
      if (attempt > 0) await sleep(BATCH_BACKOFF_MS * 2 ** (attempt - 1));
      const res = await doc.send(
        new BatchGetCommand({ RequestItems: { [table]: { Keys: keys } } }),
      );
      for (const item of (res.Responses?.[table] ?? []) as AiRunRecord[]) {
        found.set(item.runId, item);
      }
      keys = (res.UnprocessedKeys?.[table]?.Keys ?? []) as Array<{ itemId: string }>;
    }
    if (keys.length > 0) {
      log.warn({ unprocessed: keys.length }, 'ai run log: BatchGet left keys unprocessed after retries');
```

```ts
      const sets = ['#d.#t.#v = :v', '#d.#t.#va = :at'];
```

```ts
// ---------------------------------------------------------------------------
// Raw per-target op view (AI run log, design 2026-08-06 section 7.1)
// ---------------------------------------------------------------------------

/** One target as the MODEL stated it, before any folding or downgrading. */
export interface ExtractionOpView {
  op: ProposedOp;
  /** The RAW value string, KEPT even when empty - an empty value on a
   *  write/suggest is exactly the case parseExtractionText erases at :215-219. */
  value?: string;
  reason?: string;
}

export type ExtractionOpsView = Record<DecisionTarget, ExtractionOpView>;

function absentView(): ExtractionOpsView {
  const view = {} as ExtractionOpsView;
  for (const target of DECISION_TARGETS) view[target] = { op: 'absent' };
  return view;
}

/** All twelve targets absent. Frozen - callers must never mutate it. */
export const EMPTY_OPS_VIEW: ExtractionOpsView = Object.freeze(absentView());

function trimmedOr(value: unknown): string | undefined {
  return typeof value === 'string' && value.trim().length > 0 ? value : undefined;
}

/**
 * The RAW per-target op view of the model's response text.
 *
 * WHY NOT the parsed ExtractionResult (design 7.1): parseExtractionText folds
 * the address and type `none` sentinels to ABSENT (:233, :258-263), so a
 * decline is indistinguishable from a silence; and it REWRITES a write/suggest
 * whose value is unusable into { op: 'none' } while dropping the reason
 * (:215-219), so a parsed `none` means EITHER "the model declined" OR "the
 * model tried and supplied an unusable value" - and the second is precisely
 * what QA needs to see, because it is the model FAILING rather than abstaining.
 *
 * TOTAL BY CONTRACT - it never throws. Its sibling parseExtractionText throws
 * by design on malformed input, and the run log's `parse` failure kind is
 * exactly when this is handed unparseable text. On unparseable or non-object
 * input every target comes back `absent`, and the recorder then records every
 * target as not_addressed - never no_finding, because a decline that was never
 * observed must never be inferred.
 */
export function parseExtractionOps(rawText: string | undefined): ExtractionOpsView {
  const view = absentView();
  if (rawText === undefined) return view;
  let parsed: unknown;
  try {
    parsed = JSON.parse(rawText);
  } catch {
    return view;
  }
  if (!isRecord(parsed)) return view;

  // The eight scalars: fields.<name>.op, verbatim.
  const rawFields = isRecord(parsed.fields) ? parsed.fields : {};
  for (const field of EXTRACTABLE_FIELDS) {
    const rawOp = rawFields[field];
    if (!isRecord(rawOp)) continue;
    const op = rawOp.op;
    if (op !== 'none' && op !== 'write' && op !== 'suggest') continue;
    view[field] = {
      op,
      ...(typeof rawOp.value === 'string' && { value: rawOp.value }),
      ...(trimmedOr(rawOp.reason) !== undefined && { reason: clamp(String(rawOp.reason), MAX_REASON_CHARS) }),
    };
  }

  // address: the op only - no parts folding, so a `none` stays a `none`.
  const rawAddress = parsed.address;
  if (isRecord(rawAddress)) {
    const op = rawAddress.op;
    if (op === 'none' || op === 'write' || op === 'suggest') {
      view.address = {
        op,
        ...(trimmedOr(rawAddress.reason) !== undefined && {
          reason: clamp(String(rawAddress.reason), MAX_REASON_CHARS),
        }),
      };
    }
  }

  // status: the boolean IS the op.
  const rawStatus = parsed.statusAdvance;
  if (isRecord(rawStatus) && typeof rawStatus.suggest === 'boolean') {
    view.status = {
      op: rawStatus.suggest ? 'suggest' : 'none',
      ...(trimmedOr(rawStatus.reason) !== undefined && {
        reason: clamp(String(rawStatus.reason), MAX_REASON_CHARS),
      }),
    };
  }

  // type: "none" is the decline sentinel. ANY other non-empty string is the
  // model proposing something - including an off-enum value, which is a FAILED
  // ATTEMPT and must never read as a decline.
  const rawType = parsed.typeSuggestion;
  if (isRecord(rawType) && typeof rawType.value === 'string' && rawType.value.length > 0) {
    view.type =
      rawType.value === 'none'
        ? { op: 'none' }
        : {
            op: 'suggest',
            value: rawType.value,
            ...(trimmedOr(rawType.reason) !== undefined && {
              reason: clamp(String(rawType.reason), MAX_REASON_CHARS),
            }),
          };
  }

  // phone: the empty-string phone is the decline sentinel.
  const rawPhone = parsed.phoneAddition;
  if (isRecord(rawPhone) && typeof rawPhone.phone === 'string') {
    view.phone =
      rawPhone.phone.trim().length === 0
        ? { op: 'none' }
        : {
            op: 'suggest',
            value: rawPhone.phone,
            ...(trimmedOr(rawPhone.reason) !== undefined && {
              reason: clamp(String(rawPhone.reason), MAX_REASON_CHARS),
            }),
          };
  }

  return view;
}
```

```ts
// The run log's window block (design 2026-08-06 section 6.1).
//
// Stores message IDS, not message text - text is rehydrated at view time. The
// per-message `hash` is produced by renderUtteranceLine, THE SAME function that
// builds the request, so the recorded hash and the sent bytes can never
// diverge. It is NOT a \n-join of the raw utterance texts: the real renderer
// applies single-line normalization and speaker prefixes, so a naive join would
// hash bytes that were never sent and produce a permanent false mismatch on
// every run.
//
// DRIFT DETECTION, NOT REPLAY. A change to toUtterances, capUtterances,
// clampHeadTail, or the renderer changes the bytes for the same stored message,
// so a mismatch means "something changed", not necessarily "the message
// changed". windowParams records the byte-affecting CONSTANTS, so a reader can
// tell a constant change from an algorithm change: if the params match and the
// hash does not, the code changed.
import { createHash } from 'node:crypto';
import { renderUtteranceLine } from './prompt.js';
import type { TranscriptUtterance } from '../../adapters/extraction.js';
import type { RunWindow, RunWindowExcluded, RunWindowMessage } from './runTypes.js';
import {
  MAX_TRANSCRIPT_AGE_DAYS,
  MAX_TRANSCRIPT_MESSAGES,
  NEW_MESSAGE_CHAR_CAP,
  SEEN_MESSAGE_CHAR_CAP,
  TRUNCATION_MARKER,
  WINDOW_CHAR_BUDGET,
} from '../../jobs/extraction.js';

/** One message's pieces, as the job computed them. */
export interface WindowMessagePieces {
  tsMsgId: string;
  /** MessageItem.type at run time. */
  type: string;
  /** MessageItem.direction at run time. */
  direction: string;
  /** Utterances BEFORE capping. EMPTY means the message carried nothing. */
  raw: TranscriptUtterance[];
  /** Utterances AFTER capping - the exact set that reached the model. */
  capped: TranscriptUtterance[];
  /** The exact per-message cap this run applied to this message. */
  capChars: number;
}

export interface BuildRunWindowInput {
  cursor: string;
  /** How many rows listByConversation returned (to detect the fetch cap). */
  fetchedCount: number;
  /** Fetched, then dropped by the MAX_TRANSCRIPT_AGE_DAYS cutoff. */
  agedOutTsMsgIds: string[];
  /** Chronological, post-age-cutoff, in the job's own order. */
  perMessage: WindowMessagePieces[];
  /** tsMsgIds that survived the whole-window char budget. */
  included: Set<string>;
  hasInferredRoleContent: boolean;
  newestTsMsgId?: string;
}

/**
 * sha256, first 16 hex, of the EXACT rendered text this message contributed to
 * the user content.
 *
 * THE JOIN IS EXACT AND NON-NEGOTIABLE (design 6.1) - this single detail
 * decides whether every stored hash matches or every one fails: a SINGLE \n,
 * in the order toUtterances produced them (chronological, and for a call
 * transcript, line order), with NO trailing newline.
 */
export function hashRenderedMessage(utterances: TranscriptUtterance[]): string {
  const rendered = utterances.map(renderUtteranceLine).join('\n');
  return createHash('sha256').update(rendered, 'utf8').digest('hex').slice(0, 16);
}

export function buildRunWindow(input: BuildRunWindowInput): RunWindow {
  const messages: RunWindowMessage[] = [];
  const excluded: RunWindowExcluded[] = [];
  const noContent: string[] = [];
  let totalChars = 0;

  // Age exclusions first, so `excluded` reads oldest-cause-first.
  for (const tsMsgId of input.agedOutTsMsgIds) excluded.push({ tsMsgId, cause: 'age_30d' });

  for (const piece of input.perMessage) {
    if (piece.raw.length === 0) {
      // Zero utterances - the message carried NOTHING to the model. In practice
      // a call whose transcript is not `completed`. It still enters the included
      // set with size 0; recording it as READ would be a false claim that the
      // model saw a call it never saw.
      noContent.push(piece.tsMsgId);
      continue;
    }
    if (!input.included.has(piece.tsMsgId)) {
      excluded.push({ tsMsgId: piece.tsMsgId, cause: 'char_budget' });
      continue;
    }
    const rawChars = piece.raw.reduce((n, u) => n + u.text.length, 0);
    const chars = piece.capped.reduce((n, u) => n + u.text.length, 0);
    totalChars += chars;
    messages.push({
      tsMsgId: piece.tsMsgId,
      type: piece.type,
      direction: piece.direction,
      tier: piece.tsMsgId > input.cursor ? 'new' : 'seen',
      capChars: piece.capChars,
      truncated: rawChars > piece.capChars,
      chars,
      hash: hashRenderedMessage(piece.capped),
    });
  }

  return {
    cursor: input.cursor,
    ...(input.newestTsMsgId !== undefined && { newestTsMsgId: input.newestTsMsgId }),
    hasInferredRoleContent: input.hasInferredRoleContent,
    totalChars,
    // Messages beyond MAX_TRANSCRIPT_MESSAGES are never fetched, so they cannot
    // be enumerated in `excluded` without a second read this design declines to
    // pay for. An honest boolean beats implying the list is exhaustive.
    windowCappedAtLimit: input.fetchedCount === MAX_TRANSCRIPT_MESSAGES,
    windowParams: {
      newMessageCharCap: NEW_MESSAGE_CHAR_CAP,
      seenMessageCharCap: SEEN_MESSAGE_CHAR_CAP,
      windowCharBudget: WINDOW_CHAR_BUDGET,
      maxTranscriptMessages: MAX_TRANSCRIPT_MESSAGES,
      maxTranscriptAgeDays: MAX_TRANSCRIPT_AGE_DAYS,
      truncationMarker: TRUNCATION_MARKER,
    },
    messages,
    excluded,
    noContent,
  };
}
```

```ts
// Decision assembly for the AI run log (design 2026-08-06 section 7.1).
//
// Decisions are built from what the model SAID (the raw op view of rawText),
// JOINED with apply's outcomes for what we DID. Two earlier revisions got this
// wrong in opposite directions - first deriving no_finding inside apply.ts
// (which fabricates evidence of evaluation, because apply's loop treats a
// missing field and an explicit op:'none' identically), then splitting the
// source by target (which still fabricates a decline whenever the downgrade at
// schema.ts:215-219 fires). Reading rawText for ALL TWELVE targets is both
// simpler and the only correct option.
//
// JOIN RULES:
//  1. An apply outcome (wrote | suggested | dropped) wins outright.
//  2. Else proposedOp 'none'   -> no_finding   (the model explicitly declined).
//  3. Else proposedOp 'absent' -> not_addressed (never mentioned at all).
//  4. Else (write/suggest with NO apply outcome) -> dropped/invalid_value. The
//     only way a raw write/suggest reaches apply as a silent no-op is the
//     value-less downgrade at schema.ts:215-219 or the zero-usable-parts
//     address fold at schema.ts:258-263 - both are "the model supplied an
//     unusable value", which is the case QA needs to see.
//  5. rawText absent -> every target is 'absent', so NO target can be recorded
//     no_finding. The spec does not permit inferring a decline that was never
//     observed.
//  6. Verdict is DERIVED here, never passed in.
import { DECISION_TARGETS, type DecisionTarget, type RunDecision, type Verdict } from './runTypes.js';
import type { ExtractionOpsView } from './schema.js';
import type { ApplyDecision } from './apply.js';

export interface BuildDecisionsInput {
  /** parseExtractionOps(rawText), or EMPTY_OPS_VIEW when no response arrived. */
  ops: ExtractionOpsView;
  /** False when the driver produced no rawText at all (console driver, or a
   *  driver failure before a response arrived). */
  rawTextPresent: boolean;
  /** apply's per-target outcomes. Empty on a run that never reached apply. */
  applyDecisions: ApplyDecision[];
}

/** wrote -> auto_applied; suggested -> pending; everything else -> not_presented. */
function verdictFor(outcome: RunDecision['outcome']): Verdict {
  if (outcome === 'wrote') return 'auto_applied';
  if (outcome === 'suggested') return 'pending';
  return 'not_presented';
}

export function buildDecisions(input: BuildDecisionsInput): Partial<Record<DecisionTarget, RunDecision>> {
  const applied = new Map<string, ApplyDecision>();
  for (const d of input.applyDecisions) applied.set(d.target, d);

  const out: Partial<Record<DecisionTarget, RunDecision>> = {};
  for (const target of DECISION_TARGETS) {
    const op = input.ops[target];
    // Rule 5, asserted rather than assumed: a decline that was never observed
    // must never be inferred.
    const proposedOp = input.rawTextPresent ? op.op : 'absent';
    const hit = applied.get(target);

    let outcome: RunDecision['outcome'];
    let dropReason: RunDecision['dropReason'];
    if (hit !== undefined) {
      outcome = hit.outcome;
      dropReason = hit.dropReason;
    } else if (proposedOp === 'none') {
      outcome = 'no_finding';
    } else if (proposedOp === 'absent') {
      outcome = 'not_addressed';
    } else {
      outcome = 'dropped';
      dropReason = 'invalid_value';
    }

    const proposedValue = hit?.proposedValue ?? (proposedOp === 'write' || proposedOp === 'suggest' ? op.value : undefined);
    const reason = hit?.reason ?? op.reason;

    out[target] = {
      proposedOp,
      ...(proposedValue !== undefined && { proposedValue }),
      ...(hit?.coercedValue !== undefined && { coercedValue: hit.coercedValue }),
      ...(hit?.previousValue !== undefined && { previousValue: hit.previousValue }),
      ...(reason !== undefined && { reason }),
      ...(hit?.demotedFrom !== undefined && { demotedFrom: hit.demotedFrom }),
      outcome,
      ...(dropReason !== undefined && { dropReason }),
      verdict: verdictFor(outcome),
    };
  }
  return out;
}
```

# SLICE 10 - `processRow` returns a `RunDraft`; one writer, one write

This is the wiring slice. Read spec section 8 in full before starting. Three properties are non-negotiable and each has its own test:

1. **The envelope has exactly ONE writer and writes EXACTLY ONCE per run, on every terminal path.** `processRow` builds a `RunDraft` and never writes it; `runDueExtractions` performs the single write.
2. **The outer try/catch in `runDueExtractions` STAYS, as a backstop.** It is NOT replaced by the returned outcome. It provides per-row batch isolation (`app/src/jobs/extraction.ts:401-425`): `processRow` not throwing on KNOWN failures does not mean it can never throw - an unhandled defect, an OOM, or a repo path nobody enumerated would otherwise abort the entire poll batch. **The catch must still call `repo.fail`.**
3. **A skip-path `complete()` throw is a FAILURE, not a skip.** All four `repo.complete()` call sites (`:286`, `:318`, `:328`, `:378`) are `error.kind: 'complete'` with `outcome: 'failed'`, and go through the normal failure handling. Reading "it was a skip, so record `skipped`" is a silent regression: `complete()` is what clears the claim, so a throw there leaves the row CLAIMED and out of `byDueAt`, and recording it as a skip means no `repo.fail()` - hence no backoff, no attempt increment, and no park. The row would never run again and nothing would say so.

**Two branches are NOT recorded at all** and the writer must skip them explicitly now that it runs on every path (spec 6.3):
- claim-lost (`:256`) - the sliding debounce working as designed; recording it would be pure noise.
- the defensive `listedDueAt === undefined` return (`:254`) - a listed row always carries `dueAt`, so this is unreachable in practice and has no meaningful `skipReason`.

```ts
/**
 * The SINGLE envelope write, on every terminal path. STRICTLY BEST-EFFORT:
 * wrapped, logged, swallowed. It must never fail an extraction run, re-arm a
 * due row, or burn a retry attempt - observability that can break what it
 * observes is worse than none (design 8).
 *
 * Deliberately NOT idempotent: if complete() fails and the row re-arms, the
 * retry writes a SECOND run record. The model really was called twice.
 */
async function recordRun(
  deps: ExtractionJobDeps,
  outcome: RunOutcome,
  draft: RunDraft,
  nowIso: string,
): Promise<void> {
  try {
    const durationMs = Math.max(0, Date.now() - draft.startedMs);
    const record: AiRunRecordInput = {
      runId: draft.runId,
      startedAt: draft.startedAt,
      finishedAt: new Date(Date.parse(draft.startedAt) + durationMs).toISOString(),
      durationMs,
      conversationId: draft.conversationId,
      ...(draft.contactId !== undefined && { contactId: draft.contactId }),
      trigger: draft.trigger,
      outcome,
      ...(draft.skipReason !== undefined && { skipReason: draft.skipReason }),
      ...(draft.error !== undefined && {
        error: {
          kind: draft.error.kind,
          message: draft.error.message,
          attempts: draft.error.attempts ?? 0,
          parked: draft.error.parked ?? false,
        },
      }),
      // A skip that exited before the model was selected still has to name a
      // driver; the configured one is the honest answer.
      driver: draft.driver ?? deps.driver.kind,
      ...(draft.model !== undefined && { model: draft.model }),
      ...(draft.promptFingerprint !== undefined && { promptFingerprint: draft.promptFingerprint }),
      ...(draft.usage !== undefined && { usage: draft.usage }),
      ...(draft.window !== undefined && { window: draft.window }),
      ...(draft.profileFieldsPopulated !== undefined && {
        profileFieldsPopulated: draft.profileFieldsPopulated,
      }),
      ...(draft.rawText !== undefined && { rawText: draft.rawText }),
      ...(draft.rawResult !== undefined && { rawResult: draft.rawResult }),
      decisions: draft.decisions ?? {},
      notedLines: draft.notedLines ?? 0,
    };
    await deps.aiRuns.putRun(record);
  } catch (err) {
    // Ids only - never the draft, never the error's serialized payload beyond
    // its own message. A run whose record fails to write is invisible while the
    // extraction itself succeeded: the accepted cost of best-effort recording
    // (design 14). Such failures log, which is what makes them findable.
    deps.logger.warn(
      { conversationId: draft.conversationId, runId: draft.runId, err },
      'ai run log write failed (best-effort - extraction unaffected)',
    );
  }
}
```

```ts
// AI run log API (design 2026-08-06 section 9). ADMIN ONLY on the server -
// client-side route guarding alone is not authorization.
//
//   GET /api/ai-runs?scope=&before=&from=&to=&limit=  -> 200 { runs, nextBefore? }
//   GET /api/ai-runs/:runId                            -> 200 { run, window }
//
// SCOPE IS A SINGLE EXCLUSIVE SELECTOR, not a filter matrix: one Query has one
// hash key, so global / a contact / a conversation / an outcome cannot be
// combined. Only the date range composes (a BETWEEN on sortKey). Presenting
// these as independent checkboxes would promise a query the index cannot serve.
//
// PII: run records carry contact PII by design (rawText, rawResult, decision
// values). The LIST projects a summary WITHOUT them; the DETAIL returns them to
// an authenticated admin. Nothing here is ever logged.
import { Router } from 'express';
import { mergeContext } from '../lib/context.js';
import { logger as defaultLogger, type Logger } from '../lib/logger.js';
import { requireRole } from '../middleware/auth.js';
import { createAiRunsRepo, DEFAULT_PAGE_SIZE, type AiRunRecord, type AiRunsRepo } from '../repos/aiRunsRepo.js';
import { createMessagesRepo, type MessagesRepo } from '../repos/messagesRepo.js';
import { DECISION_TARGETS } from '../services/extraction/runTypes.js';

export interface AiRunsRouterDeps {
  logger?: Logger;
  aiRunsRepo?: AiRunsRepo;
  messagesRepo?: Pick<MessagesRepo, 'getByTsMsgId'>;
}

/** Hard ceiling on a page, so a hand-crafted limit cannot fan out a BatchGet. */
const MAX_PAGE_SIZE = 100;
const OUTCOMES = ['applied', 'no_op', 'skipped', 'failed'];
/** The exact scope forms the byEntity index can serve (design 5.3). */
const SCOPE_PATTERN = /^(global|outcome#(applied|no_op|skipped|failed)|conversations#[\w.-]+|contacts#[\w.-]+)$/;

function isValidScope(scope: string): boolean {
  return SCOPE_PATTERN.test(scope);
}

/** Per-outcome counts for the list row - never the values themselves. */
function decisionCounts(run: AiRunRecord): Record<string, number> {
  const counts = { wrote: 0, suggested: 0, dropped: 0, no_finding: 0, not_addressed: 0, pending: 0 };
  for (const target of DECISION_TARGETS) {
    const d = run.decisions[target];
    if (d === undefined) continue;
    counts[d.outcome] += 1;
    if (d.verdict === 'pending') counts.pending += 1;
  }
  return counts;
}

export function createAiRunsRouter(deps: AiRunsRouterDeps = {}): Router {
  const log = deps.logger ?? defaultLogger;
  const aiRuns = deps.aiRunsRepo ?? createAiRunsRepo({ logger: deps.logger });
  const messages = deps.messagesRepo ?? createMessagesRepo({ logger: deps.logger });

  const router = Router();
  // Every route here is admin-only (a VA gets 403). Mirrors routes/system.ts.
  router.use(requireRole('admin'));

  router.get('/', async (req, res) => {
    const scope = String(req.query['scope'] ?? 'global');
    if (!isValidScope(scope)) {
      res.status(400).json({ error: 'invalid_scope' });
      return;
    }
    const rawLimit = Number(req.query['limit']);
    const limit = Number.isFinite(rawLimit) && rawLimit > 0
      ? Math.min(Math.floor(rawLimit), MAX_PAGE_SIZE)
      : DEFAULT_PAGE_SIZE;
    const before = typeof req.query['before'] === 'string' ? req.query['before'] : undefined;
    const from = typeof req.query['from'] === 'string' ? req.query['from'] : undefined;
    const to = typeof req.query['to'] === 'string' ? req.query['to'] : undefined;

    const page = await aiRuns.listByEntity(scope, {
      limit,
      ...(before !== undefined && { before }),
      ...(from !== undefined && { from }),
      ...(to !== undefined && { to }),
    });
    const runs = page.entries.map((e) =>
      e.expired
        ? { runId: e.runId, sortKey: e.sortKey, expired: true as const }
        : {
            runId: e.runId,
            sortKey: e.sortKey,
            expired: false as const,
            startedAt: e.run.startedAt,
            durationMs: e.run.durationMs,
            conversationId: e.run.conversationId,
            ...(e.run.contactId !== undefined && { contactId: e.run.contactId }),
            trigger: e.run.trigger,
            outcome: e.run.outcome,
            ...(e.run.skipReason !== undefined && { skipReason: e.run.skipReason }),
            ...(e.run.error !== undefined && { errorKind: e.run.error.kind }),
            driver: e.run.driver,
            ...(e.run.model !== undefined && { model: e.run.model }),
            decisionCounts: decisionCounts(e.run),
            notedLines: e.run.notedLines,
          },
    );
    log.debug({ scope, count: runs.length }, 'ai run log listed');
    res.json({ runs, ...(page.nextBefore !== undefined && { nextBefore: page.nextBefore }) });
  });

  return router;
}
```

## SPEC CONCERNS

The spec is APPROVED and frozen; everything above is planned TO IT AS WRITTEN. These are the points where I would have chosen differently or where the spec is silent, recorded rather than silently deviated from.

**1. Under-specified: the outcome when `rawText` proposed `write`/`suggest` but the parse folded it away.**
Spec 7.1 is explicit that this case must be visible and must NOT read as `no_finding` ("the second is precisely the case QA needs to see, since it is the model failing rather than abstaining"), but it never names the `outcome`/`dropReason` to record. `apply.ts` never sees these ops: `schema.ts:215-219` rewrites a value-less write/suggest to `{ op: 'none' }`, and `schema.ts:258-263` drops a zero-usable-parts address. So the join has no apply outcome to attach.
**Ruled in-plan (Task 17, rule 4):** `outcome: 'dropped'`, `dropReason: 'invalid_value'` - the same reason `apply.ts:175` uses for the identical cause (an unusable value), and the only option that satisfies 7.1's "must not read as a decline". Flagged here because a reviewer inheriting the spec alone would not find this rule in it.

**2. Under-specified: `startedAt` under the dev tick.**
`app/src/routes/dev.ts:373` deliberately advances the tick clock to `now + aiExtractionDebounceMs + 1000` so a just-scheduled due row is already past its sliding `dueAt`. Since the run's `sortKey` is `<startedAt>#<runId>` and `startedAt` is the poll clock, every dev-tick run is stamped ~one debounce window in the FUTURE. **Ruled in-plan (Task 20):** keep `startedAt = nowIso`, because it keeps the run's sort position monotonic with the due row that produced it and matches how everything else in this job stamps time; `durationMs` is real elapsed wall time. A reviewer may reasonably prefer real wall-clock `startedAt` plus a separate `pollClock` field; that would be a spec change, not a plan change.

**3. Naming nit: `driver` and `model` on `SystemFlags`.**
Spec 9 names the four new flags verbatim as `aiExtractionEnabled`, `driver`, `model`, and `promptFingerprint`. `SystemFlags` already carries `messagingDriver` (`app/src/services/systemStatus.ts:71`), so a bare `driver` sitting next to it is ambiguous at every read site - `extractionDriver` and `aiExtractionModel` (the config's own names, `app/src/lib/config.ts:336`, `:338`) would be unambiguous. **Planned to the spec as written** (Task 25). Cheap to rename later; flagged so the ambiguity is a known choice rather than an oversight.

**4. Watch item, not a concern: the `runWindow.ts` <-> `jobs/extraction.ts` import cycle.**
`runWindow.ts` imports the six byte-affecting constants from `jobs/extraction.ts`, and `jobs/extraction.ts` imports `buildRunWindow`. ESM tolerates this for hoisted declarations and call-time constant reads, but it is fragile. Task 16 Step 4 names the escape hatch (move the constants into `runTypes.ts` and re-export them from the job for backward compatibility). Consider doing that preemptively.

**5. Watch item: the window computation moves BEFORE the freshness gate.**
Spec 6.3 requires a `no_new_client` skip to record a fully computed window, which forces the cap/budget computation (today `jobs/extraction.ts:337-356`) above the gate at `:316`. That is a pure, I/O-free reorder, but it spends the capping CPU on every skipped run - and skips are the common case at steady state. The seven existing `h.seen[0].transcript` `toEqual` assertions are the regression net (Task 19 Step 4); if profiling ever shows this matters, the fix is to compute lazily behind a memo, not to drop the window.

**6. Verified: the spec's enumeration of write and verdict-resolution surfaces is COMPLETE.**
Grepped `app/src/`: `deleteSuggestion` has exactly six call sites (`routes/suggestions.ts:185`, `:235`, `:270`, `:304`, `:339`; `routes/contacts.ts:1323`), `putDismissal` exactly one (`routes/suggestions.ts:334`), and `putSuggestion` exactly one production path (`services/extraction/apply.ts:471`, via `putSuggestionSafe`, with five callers). `app/src/lib/seedData.ts` writes NO `sugg#` rows, and no dev seam mutates them outside the reseed table wipe (`app/src/lib/devReset.ts:75`, which iterates `TABLES` and therefore picks up `ai_runs` automatically once Task 1 registers it).
