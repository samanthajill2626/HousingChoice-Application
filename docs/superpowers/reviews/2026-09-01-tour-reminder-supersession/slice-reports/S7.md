## 3. THE SHIPPED WIRE SHAPE (for S9's e2e re-points and the reviewers)

`GET /api/tours/:tourId/reminders` ->

```
{
  reminders: TourReminderView[],   // the CURRENT generation, dueAt ASC. unchanged
  timezone: string,                // unchanged
  next?: TourReminderView,         // from reminders[] alone. unchanged
  earlier?: TourReminderEarlierView[]   // NEW. OMITTED when empty
}
```

`TourReminderEarlierView`, key by key, in emission order:

```
reminderId : string                                   always
kind       : ReminderKind                             always
dueAt      : string (ISO)                             always
state      : 'upcoming'|'sent'|'canceled'|'skipped'   always
body       : string        ONLY when the row has `sentBody` (the claim-time
                           snapshot). NEVER composed, never ''. ABSENT otherwise.
sentAt     : string        when present on the row
canceledAt : string        when present on the row
skippedAt  : string        when present on the row
skipReason : ReminderSkipReason   when present on the row
suppression: { reason: 'superseded' }   ONLY when state === 'upcoming'
```

NOT emitted here, on purpose: **`overdue`** (nothing will ever send an earlier
rung, and the panel's chip ladder already ranks `superseded` above `overdue`;
omitting the flag means the two cannot disagree) and any recipient-state
estimate (`suppressionOf` is never consulted - an opt-out or quiet-hours wait
would be a claim about a send that is not going to be attempted).

Ordering: `(sentAt ?? dueAt)` DESCENDING, `reminderId` ASCENDING on a tie.
Total and stable across requests.

New log field on `'tour reminders read'`: `earlierCount`. Read it WITH `count` -
a tour whose whole ladder moved reports `count: 0`, which alone looks like a
tour that was never armed.

Panel DOM (`RemindersPanel.tsx`): `<details class=earlier>` >
`<summary>Earlier reminders (N)</summary>` > `<ul class="rows earlierRows">` >
`<li class=row>`. Summary text is exactly `Earlier reminders (N)`. The only
interactive element inside is `aria-label="Cancel the earlier <kind> reminder"`.

   it."** The server DOES narrow it - O5 requires `body` to be optional - so the
   cheap shape was never available. O5 is right and C 2.4's paragraph is stale;
   note it if anyone re-reads that file.
2. **Two S6 tests had to be re-pointed, and neither is a contract conflict.**
   `tourRemindersApi.test.ts`'s "chips a pointer-mismatched pending rung" and
   "a SENT rung of a replaced ladder carries no suppression" both asserted
   against `reminders[]`; the rows they describe are now `earlier[]` rows
   carrying the SAME annotations. Both cases were rewritten in place with an
   `S7 RE-POINT` comment and both keep their original subject. The prompt asked
   me to STOP if such a break revealed a conflict - it does not: S6's own report
   section 9 predicted this move exactly.
3. **The worklist's S7 fast-gate list omits `TourDetail.test.tsx`**, which is
   the only other file that mocks `getTourReminders`. It passes unchanged (its
   mock returns `{ reminders: [] }` and the panel defaults `earlier` to `[]`),
   but it is the right blast-radius file for this slice.
4. **`nextReminderRefetchDelay` is fed `state.reminders` only, and that is now
   load-bearing rather than incidental.** An earlier rung must never anchor the
   20s overdue re-check - it never flips - and the partition means the panel
   can no longer be handed one in `reminders[]`. S5's two `superseded` guards
   inside that helper are consequently belt-and-suspenders now; they cost
   nothing and stay.
